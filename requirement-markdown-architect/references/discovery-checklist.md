# Requirement Discovery Checklist

## 1. 业务背景

- 这次需求为什么要做
- 不做会造成什么问题
- 目标指标是什么
- 是新增能力、补齐短板、还是重构优化

## 2. 用户与角色

- 目标用户是谁
- 涉及哪些操作角色
- 每个角色分别做什么
- 是否存在权限差异

## 3. 范围边界

- 本次明确包含什么
- 本次明确不包含什么
- 哪些内容容易被误解为本次范围

## 4. 模块拆分依据

- 是否已有业务模块划分
- 是否需要按角色、流程、领域对象重新拆分
- 是否存在跨模块复用能力

## 5. 功能细节

每个模块至少确认：

- 入口在哪里
- 用户触发什么动作
- 系统要完成什么处理
- 成功结果是什么
- 失败结果是什么
- 是否有状态流转
- 是否有批量、撤销、回退、重试等特殊操作

## 6. 数据与系统

- 涉及哪些核心数据对象
- 是否新增、修改、删除现有数据
- 是否依赖接口、消息、定时任务、第三方系统
- 是否影响现有流程或历史数据

## 7. 规则与限制

- 业务规则是什么
- 是否有时间、次数、身份、地区、渠道限制
- 是否有兼容旧逻辑的要求
- 是否有性能、安全、审计、合规约束

## 8. 风险与问题

- 当前已知问题有哪些
- 哪些点信息不足
- 哪些点有较大实现风险
- 哪些点需要产品、业务、研发共同确认

## 9. 输出要求

在最终 Markdown 中至少明确：

- 模块总览
- 每个模块的功能点与职责
- 每个功能点具体要做什么
- 已知问题与待确认项
- 实现、联调、测试注意点
- 跨模块依赖和整体风险
