# Test Acceptance Workflow

## Overview

在本项目中，功能代码完成后不要直接结束任务。先读取 `docs/agents/rules/test-acceptance-best-practice.md`，再按本 skill 的流程完成测试分层、验收清单和风险说明。  
本 skill 适用于前端页面/组件、后端接口/服务、以及前后端联动流程，不限定技术栈。

## Workflow

### 1. 建立上下文

- 先读取 `docs/agents/rules/test-acceptance-best-practice.md`
- 找到当前变更对应的 `docs/features/<timestamp-feature>/spec.md`、`plan.md`、`task.md`
- 结合代码变更范围，识别受影响的页面、组件、接口、服务、数据表、副作用和外部依赖
- 明确本次属于前端、后端还是前后端联动
- 不要只根据文件数量判断风险，要根据行为变化判断风险

### 2. 判断影响范围

按以下方式分类：

- 前端：页面、组件、样式、路由、交互、表单、前端状态管理、前端权限
- 后端：接口、服务、任务、数据库、缓存、消息、第三方回调、权限校验
- 前后端联动：接口契约变化、字段语义变化、跨端主流程变化、页面行为依赖后端逻辑变化

如果同一次改动同时影响多个区域，按“前后端联动”处理。

### 3. 判断风险等级

使用以下标准：

| 风险等级 | 判定标准 | 最低要求 |
| --- | --- | --- |
| 低风险 | 文案/样式微调、纯校验、转换、常量、无状态逻辑 | 快速测试 + 验收清单 |
| 中风险 | 页面交互增强、表单校验变化、单端业务逻辑变化、单表写操作、已有接口行为变化 | 快速测试 + 集成测试 + 验收清单 |
| 高风险 | 前后端联动、权限/路由/状态流转、多表更新、事务、订单/金额、异步、回调、并发、第三方依赖 | 快速测试 + 集成测试 + Smoke/人工验收项 + 验收清单 |

以下情况默认上调风险等级：

- 涉及数据库写操作、状态变更、外部依赖、异步任务：至少 `中风险`
- 涉及核心页面流程、前后端契约变化、订单、金额、权益、核心相册链路、点位配置链路：按 `高风险`

### 4. 决定测试层级

不要默认把所有变更都写成同一种测试。优先选择稳定、成本低、可重复执行的测试层级：

- 前端快速测试：组件、Hook、工具函数、校验逻辑、状态转换
- 前端集成测试：页面交互、表单提交流程、关键组件组合行为
- 后端快速测试：规则逻辑、校验器、转换器、工具类、轻量业务逻辑
- 后端集成测试：接口、数据库读写、事务、多表关系、关键业务链路
- 前后端 Smoke/人工验收：适合高风险需求，验证测试环境关键主流程
- 手工调试脚本：只用于联调或排障，不纳入自动化门禁

选择时遵守以下原则：

- 只改前端展示和交互时，优先补前端快速测试和页面交互验证
- 只改后端逻辑和数据流时，优先补后端快速测试和集成测试
- 改动跨端契约、字段语义、主流程联动时，必须补前后端联动验收项

### 5. 补齐验收清单

- 更新当前 feature 的 `task.md`
- 使用 [references/acceptance-checklist-template.md](references/acceptance-checklist-template.md) 中的模板
- 至少覆盖：
  - 成功路径
  - 输入校验
  - 边界条件
  - 异常路径或错误态
  - 回归影响点
- 如果影响前端，追加 UI 渲染、关键交互、加载态/空态/错误态、响应式/兼容性
- 如果影响后端，追加接口契约、数据库副作用、幂等性
- 如果影响前后端联动，追加主流程联调和关键字段映射核对
- 涉及异步、回调、并发时，必须追加专项验收项

### 6. 执行与输出

输出结果时，必须明确写出：

- 影响范围：前端、后端或前后端联动
- 风险等级
- 已补齐的自动化测试层级
- 需要的人工 smoke 项
- 当前测试缺口和剩余风险

如果当前环境无法补齐自动化测试，不要假装完成，必须补充：

- 缺失的测试项
- 无法补齐的具体原因
- 当前风险
- 替代性的人工验收方案

### 7. 项目内特殊约束

- 不要依赖默认 `prod` profile 作为测试前提
- 不要依赖真实线上数据或人工维护的固定生产 ID
- 不要把无断言调试类当成自动化测试结论
- 不要把“页面能打开”当作“前端已验收”
- 不要只写“已自测”，必须列出具体验收项

### 8. 完成标准

只有满足以下条件，才可以把需求视为完成：

- 已明确影响范围
- 已完成风险分级
- 已确定并执行对应测试层级
- 已更新当前 feature 的 `task.md` 验收清单
- 已说明自动化验证、人工验收和剩余风险
