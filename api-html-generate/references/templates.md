# API HTML Templates

## 新增 API HTML 模板

新增 API 页面应相对完整，通常包含以下章节：

```text
1. 页面头部摘要
2. 调用概览 / 关键说明
3. 请求说明
4. 响应说明
5. 字段详情
6. 异常 / 错误说明
7. 请求示例
8. 响应示例
9. 页脚来源说明（如有）
```

推荐内容结构：

- 接口名称
- 接口用途简介
- 请求方式
- 接口路径
- 鉴权要求
- 公共参数 / Header
- 请求参数表
- 响应顶层结构表
- 嵌套字段表
- 特殊字段说明
- 异常 / 错误说明
- 请求示例
- 响应示例

生成原则：

- 信息不足时，用“待补充”“未提供”“未确认”明确标注。
- 如果字段层级复杂，拆多个表，不要强塞一张表。
- 先给总览，再给字段细节，再给示例。

## 修改 API HTML 模板

修改 API 页面只说明变更部分，推荐结构如下：

```text
1. 页面头部摘要
2. 变更概览
3. 详细变更
4. 兼容性影响
5. 更新后的示例（如有）
6. 页脚来源说明（如有）
```

详细变更按实际命中项展开：

- 接口路径变更
- 请求方式变更
- 认证要求变更
- 请求参数新增
- 请求参数删除
- 请求参数调整
- 响应字段新增
- 响应字段删除
- 响应字段调整
- 错误码 / 异常说明变更
- 示例变更

每一项变更至少说明：

- 变更前
- 变更后
- 影响说明

生成原则：

- 只说明本次改动，不重复展开未变化部分。
- 如果本次没有某类改动，不要硬凑内容。
- 如果用户明确要求完整重写，再按新增 API 模板输出。

## 通用 HTML 结构建议

无论新增还是修改，都建议包含以下 HTML 组成：

- 完整 `<!doctype html>` 文档
- `head` 中包含 `meta charset`、`viewport`、`title`
- 内联 `style`，保证文档可独立打开
- `body` 中使用主容器包裹全部内容
- 顶部 header 展示标题、简介、方法和路径
- 使用目录导航快速跳转主要章节
- 表格、卡片、note、代码块等组件保持统一样式

## 输出要求

- 输出必须是可直接打开的完整 HTML。
- 视觉风格必须参考 `design.md`。
- 修改类页面必须明显体现“变更说明”属性。
- 新增类页面必须明显体现“完整接口说明”属性。
